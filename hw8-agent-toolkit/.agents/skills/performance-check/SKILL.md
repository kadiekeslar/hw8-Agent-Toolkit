# Performance Check

- Establish the workload and performance concern; inspect the relevant path for repeated work, costly I/O, or scaling problems.
- Use existing timing, profiling, or benchmarks when practical and authorized. Record command, workload, environment, and actual measurements.
- Label findings MEASURED or SUSPECTED, cite code/evidence, and explain likely user impact and a focused next measurement or improvement.
- Do not present estimates as benchmarks. Report only unless optimization edits are requested; after edits compare equivalent workloads.
